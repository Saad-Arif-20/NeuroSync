## Caveats to state honestly in the report
- One subject, no hyperparameter search, final epoch reported (no test-set epoch selection). E07 (notebook, seed 0 stream) gave 30.0%; repo code over 3 seeds gave 23.5-30.0% top-1, so quote the range/mean (26.5% top-1, 54.8% top-5), not the best run.
- Shuffled control at 1.0%/5.0% is 2/200 and 10/200 correct: consistent with chance on a 200-item test set (noise is about +/-0.7 pts on top-1).
- Original transformer encoder (24.5% / 49.5%) is within the baseline's seed range: the existing NeuroSync architecture is viable.
- Higher than the paper: differences in setup (80-rep test averaging, LAION CLIP backbone, small encoder) - not a claimed improvement.
- THINGS-EEG2 block-design confound: needs fair baselines/discussion.
- Colab outputs are not saved: screenshots are the only record until the notebook is re-run.

- E10: each subject is trained and tested separately (within-subject), not cross-subject. Seeds here (0,1,2 via torch.manual_seed per run) differ from the earlier repo seed sweep (E09), so subject 1 reads 25.7% mean here vs 26.5% in E09: same setup, different random draws, which itself shows the run-to-run noise (~2-5 pts per subject).
- E10: numbers were read from the Colab output screenshot; the notebook outputs are not saved. Per-subject means cross-check against the printed across-subject means (30.5 / 61.9).
- E10: the pasted cell's header comment differs slightly from experiments/colab_multisubject.py (comment lines only); code is identical.
- E11: the Transformer is the ORIGINAL NeuroSync encoder with no tuning (built for 64-channel, 1000-sample input; here 17x100, so the conv stack leaves only 6 time steps for 4 attention layers). It shows this untuned configuration is worse, NOT that Transformers are worse for EEG. Per-subject differences are 2-17 points, larger than seed noise (about 2-5 points).
- E11: baseline numbers are the E10 per-subject means (rounded to 0.1), hard-coded in the script; the baseline was not re-run in the same session. Seeds and protocol are identical.
- E11: the 'subjects where transformer better' count was cut off on screen; every printed per-subject difference is negative, so it is 0 of 10.
- E12: the improvement is modest. Single-model gain +1.5 top-1 (SD 2.3 across subjects) is only a little larger than seed noise (2-5 pts per subject); subject 6 got worse (33.0 vs 36.5). The ensemble gain (+3.1) uses 3 models per subject, so it costs 3x compute and is not a like-for-like comparison with a single model.
- E12: Phase A is small (12 runs, 6 paired comparisons, one went the wrong way) and its validation split uses only 4-repetition EEG (noisier than the 80-rep test), so the +2.0 validation gain is weak evidence, which is why the claim is kept modest.
- E12: baseline numbers are E10 per-subject means (rounded to 0.1) from an earlier session; the baseline was not re-run alongside. Seeds are the same, augmentation randomness is new.
- E12: numbers read from Colab output screenshots (output is not saved). The 'better in 9/10' counts are as printed by the script.
- E13 (negative result): blur-prior targets did NOT help against unblurred candidates in this setup. This does not show the published method fails: the paper gives no numeric sigma, uses a different image backbone by default (RN50 vs our ViT-B/32), a different EEG encoder and training recipe, and its text (as read) does not say how test candidates are encoded. Possible explanations are untested.
- E13: the higher 'matched-gallery' scores come from also blurring the candidate images, which is a different and easier retrieval task (not comparable to the 200-way benchmark on original images). It is reported for transparency only; the decision used the unblurred-candidate score.
- E13: Phase A is small (3 subjects x 2 seeds, 200 validation images, EEG with only 4 repetitions per image), so differences of about 1-2 points are within noise; the honest reading is 'no evidence of gain', not 'proven useless'.
- E14: differences between backbones are 1-2 points on 3 subjects x 2 seeds with 200 validation images, so they are within noise; the reading is 'no evidence that a different backbone helps', not 'ViT-B/32 is best'. Larger models were not better, which is plausible because 200-way retrieval gets harder only through the EEG side here; this explanation is untested.
- E14: the first attempt on 19-Nov was lost (Colab session ended before the output was saved); the script and decision rule were committed before running (1d42317), and this is the rerun of the same script.
- E15: layer, teacher and weight were chosen on validation only (3 subjects x 2 seeds, 200 held-out images, 4-rep EEG); the test set was used once, for the pre-chosen configuration. Still, many candidates were compared on a small validation set (winner's curse is possible for the exact layer/weight), but the gain (+13.8 val, +19.4 test) is far above the 2-point rule and consistent in 10/10 subjects.
- E15: the z-scored similarity fusion and train-mean centring are my own design choices, not copied from a paper. Fusion happens at test time on similarity matrices; no test labels are used for fusion, weights or selection.
- E15: the two teachers are different image encoders applied to the same 200 test images; the model still never sees test EEG or test images in training. The shuffled-label control (0.5/1.5) shows the score depends on correct EEG-image pairing. Only S01 was controlled.
- E15: DINOv2 layer indices are Hugging Face hidden_states indices (0 = embeddings). Published numbers above ours (e.g. HVF, DTHA) are recent preprints with different pipelines (250 Hz, other encoders); our 53.0 top-1 is on 100 Hz released files and is not claimed to be like-for-like. Our E15 gain is not yet repeated by an independent re-run.
- E16: the fusion weights and the layer/model choices were picked on validation only (3 subjects x 2 seeds, 200 images); about 15 candidates were compared, so winner's curse is possible for the exact choice. The test set was used once for the chosen configuration. The test gain (+3.3 +/- 2.0 top-1) is smaller than the validation gain (+4.4), which fits mild optimism on validation.
- E16: the E15 numbers used for the paired comparison are the per-subject values from the E15 Colab output screenshot (E15F in the script), not a fresh re-run of E15.
- E16: I accidentally navigated the Colab tab away mid-run; the run survived and the output reattached, and the per-subject lines printed are from the reattached output. One session (S01-S10) of the same script, no re-run.
- E17 (CSLS): CSLS needs the whole set of 200 unlabelled test EEG queries and its k=1 setting benefits from the benchmark structure (each of the 200 gallery images is the target of exactly one query). It cannot be used for decoding a single recording on its own. It is reported as a separate transductive result and must not be mixed with the plain top-1/top-5 or compared directly with papers that report plain retrieval.
- E17: the MLP architecture, the recipe (batch 1024, 25 epochs, lr 5e-4, cosine with warmup) and CSLS come from preprint papers (arXiv 2602.07495, 2609.02582) read as text; we re-implemented them ourselves and our numbers are not a reproduction of theirs. Our data are the released 100 Hz files, not 250 Hz.
- E17: encoder (mlp0 vs mlp vs cnn) and CSLS k were chosen on the small validation set (3 subjects x 2 seeds, 200 images); mlp0 vs mlp differ by under 1 point on validation (within noise), so the choice of dropout 0 is weakly supported. The test set was used once for the chosen configuration. Fusion weights were inherited from E16 (chosen on validation in E16).
- E17: the shuffled-label control was run on S01 only (plain 1.0/4.0, near chance); top-5 4.0 is about 1.4 standard errors above 2.5 on 200 samples. The E15/E16 baselines in the paired comparison are the earlier per-subject values, not re-run.
- E18 (bug): the spatial-filter-bank arm (sbk, sbke100) scored near chance because I initialised all 16 spatial filters at exactly zero, so they stay identical and the encoder only averages the channels (no spatial diversity). This is an implementation fault, not evidence that a spatial filter bank does not help; the idea is untested. The test result does not depend on sbk (sbk never won).
- E18: the winner (mlp0 + catL12) was picked among 16 (encoder, epochs, fusion) combinations on a small validation set (3 subjects x 2 seeds, 200 images); some of the +5.0 validation gain may be optimism. The test gain (+5.0 +/- 2.6, 10/10 subjects) is about the same as validation, which is reassuring but is one run.
- E18: 100 epochs was worse than 25 on validation (single teachers lower by 1-6 points); this is on this data and recipe only, not a general statement about longer training (the cited paper trains 250 epochs with a different encoder and 250 Hz data).
- E18: published plain numbers are not like-for-like (preprints, 250 Hz data, own pipelines, different seeds and averaging). Our 80.0 plain is on the released 100 Hz files with our own re-implementation; it should be described as competitive with recent preprints, not as a record. The CSLS number (92.5) uses the whole unlabelled test set and the one-to-one structure of the benchmark and must not be compared with plain retrieval.
- E18: E17 per-subject numbers used for the paired comparison are the values from the E17 Colab output (E17P/E17C lists in the script), not a fresh re-run.
